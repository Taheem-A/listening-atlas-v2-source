# Listening Atlas source export

This archive contains the editable source for Listening Atlas. The analysis-export-v3 branch upgrades the ChatGPT-facing export from a compact profile to an analysis-grade JSON package. It contains no hosted environment-variable values, access tokens, credentials, `node_modules`, build output, or runtime data.

## Directory structure

- `public/` — browser HTML, CSS, UI controller, analytics engine, profile exporter, enrichment client, and Web Worker.
- `server/` — Cloudflare Worker entrypoint, API routes, Spotify client-credentials integration, and D1 metadata cache.
- `db/` — Drizzle source schema for the persistent Spotify metadata cache and enrichment-control lease.
- `drizzle/` — generated SQL migration and Drizzle migration metadata used by Sites during deployment.
- `tests/` — analytics, import/storage, profile-export, enrichment, Spotify-client, rate-limit, and D1-cache regression tests.
- `scripts/build.mjs` — builds the Worker-compatible production output under `dist/`.
- `package.json` and `package-lock.json` — project scripts and pinned development dependencies.
- `vite.config.js` — local Vite development configuration.
- `.openai/hosting.json` — existing ChatGPT Sites project identity and logical D1 binding.
- `.env.example` — required environment-variable names with blank values.
- `REVIEW.md` — implementation review for the duration-enrichment upgrade.

`dist/` and `server/assets.generated.js` are generated by the build and are intentionally excluded from this source archive.

## Install dependencies

Install Node.js with npm, open a terminal in the extracted `listening-atlas-v2-source` directory, and run:

```bash
npm ci
```

## Run tests

```bash
npm test
```

## Run locally

Start the Vite development server:

```bash
npm run dev
```

Vite prints the local URL to open. The local development middleware intentionally runs without hosted Spotify secrets, so the application remains usable while Spotify metadata shows as unconfigured. Raw listening history stays in the browser's IndexedDB database.

Create a production build with:

```bash
npm run build
```

The build generates `dist/server/index.js`, copies `.openai/hosting.json`, and includes the Drizzle migrations under `dist/.openai/drizzle/`.

## Sites and D1 deployment configuration

`.openai/hosting.json` identifies the existing Listening Atlas Site and declares the logical D1 binding:

```json
{
  "project_id": "appgprj_6a9b5fdd79bc8191820698b15b3e1e4e",
  "d1": "DB"
}
```

ChatGPT Sites supplies the actual production D1 database as `env.DB`. During deployment, Sites applies the migration in `drizzle/0000_lumpy_drax.sql`, which creates `spotify_track_metadata` and `spotify_enrichment_control`. The application stores imported listening history locally in IndexedDB; D1 stores only Spotify track metadata and enrichment-control state.

To deploy this source as an update to the existing Site, use the ChatGPT Sites workflow with the existing `project_id`. Do not create a replacement Site. A deployment build must contain the Worker entrypoint, hosting manifest, and migrations described above.

## Environment variables

The hosted runtime uses:

- `SPOTIFY_CLIENT_ID` — Spotify application client ID.
- `SPOTIFY_CLIENT_SECRET` — Spotify application secret; configure it as a hosted secret and never expose it to browser code.
- `SPOTIFY_ANALYTICS_PERMISSION` — set to `granted` only when enrichment is authorized for this application.

Copy `.env.example` only as a reference. Keep real values outside source control and configure production values in the Site's Environment variables settings. Without these variables, Listening Atlas still imports and analyzes history; Spotify duration enrichment remains unavailable.


## Analysis export schema v3

The analysis export is designed to be self-contained for downstream analysis. It includes:

- selected, previous, 7/30/90/180-day, and all-time aggregate summaries;
- full all-time track, artist, and album catalogs with selected/previous/all-time metrics;
- duration values and provenance for known tracks;
- full current-vs-previous momentum lists;
- daily, hour-of-day, and weekday summaries;
- normalized event-level music history with playback-end timestamp, played milliseconds, identity, skip flag, platform, start/end reason, country, shuffle/offline/incognito context, duration source, and raw/capped completion;
- explicit data-quality and field-coverage information.

It intentionally excludes credentials, IP addresses, decrypted user-agent strings, raw Spotify API response objects, audio, artwork, and lyrics.
